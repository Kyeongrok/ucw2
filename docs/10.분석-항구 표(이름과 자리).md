# 항구 표 — 이름과 세계지도 위 자리

한 줄 답: **20~22바이트 레코드가 130개** 이어지는 표가 있고, **리스본이 0번**이다.
좌표는 세계지도의 **칩 눈금**(0~2159 / 0~1079)이다.

![lisbon](lisbon.png)
0번 리스본. `PORTMAP.LZW` 의 0번 지도(96x96 칸)를 `CHIP_NO.DAT[0]` 이 가리키는 0번 칩 벌로 그린 것이다.

## 레코드

```
[0]      나라·문화권 한 바이트   (뜻은 아직 안 갈렸다)
[1..2]   x  (u16 LE, 칩 눈금)
[3..4]   y  (u16 LE, 칩 눈금)
[5..]    이름, NUL 로 채움
```

**이름 칸 길이가 판마다 다르다.**

| 파일 | 자리 | 레코드 | 글자 |
|---|---|---:|---|
| DOS `MAIN.EXE` | `0x040903` | 20 (이름 15) | 한글 cp949 |
| DOS `KOUKAI2.DAT` | `0x0053BA` | 20 | 한글 — EXE 것과 바이트까지 같다 |
| Win95 `KOUKAI2.DAT` | `0x0075E4` | **22** (이름 17) | 한글 |
| Win95 `KOUKAI2-han8.exe` | `0x053624` | 22 | 한글 |
| Win95 `KOUKAI2.EXE` | `0x05C7DF` | 20 | **일본어 cp932** — 이식판은 원본 이름을 그대로 뒀다 |

자리도 레코드 크기도 갈리므로 **찾아서 읽는다** — 좌표가 지도 안에 들고 이름이 NUL 로
끝나는 레코드가 예순넷 넘게 이어지는 자리를 훑는다(`PortTable.Find`).

## 좌표가 맞는지

서에서 동으로 리스본 120 · 세빌리아 142 · 발렌시아 178 · 바르셀로나 194 · 마르세이유 212 ·
제노바 230 · 베네치아 258 · 이스탄불 352 — **실제 차례 그대로**다.

눈금은 **1도에 여섯 칩**이다(2160/360). 리스본(-9.14도)과 이스탄불(28.98도)로 재면
232칩 / 38.12도 = **6.09** 로 맞는다. 위도도 리스본(38.72도)과 베네치아(45.44도)로 재면
40칩 / 6.72도 = 5.95 로 맞는다.

```
경도 = 칩x / 6 - 29.1
위도 = 98.4 - 칩y / 6
```

경도 원점이 -180 이 아니라 **약 29.1도 서**다 — 지도 왼쪽 끝이 대서양 한가운데다.
위도 쪽은 위 끝이 90도를 넘게 나오는데(98.4), 지도 맨 위 몇 줄이 덧댄 자리로 보인다.
**이 두 상수는 아직 어림이다.**

## 지도는 101장, 표는 130줄

`PORTMAP.LZW` 는 101장, `CHIP_NO.DAT` 은 100칸인데 이름표는 130줄이다.
뒤쪽은 배로 못 가는 내륙 도시이거나 안 쓰는 자리로 보인다 — **아직 안 갈렸다.**
