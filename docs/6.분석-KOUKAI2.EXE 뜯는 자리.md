# KOUKAI2.EXE (Win95 이식판) — 뜯는 자리

대상: `바탕화면/DH2W95Kor_Win_Test2/KOUKAI2.EXE`, 444,416바이트.
**평범한 32비트 PE** 라 3편 `CDS_95.EXE` 뜯던 방식(`PeImage` + capstone)이 그대로 통한다.

DOS 판 `MAIN.EXE` 는 16비트 볼랜드 라지 모델이라 손이 많이 간다. **데이터는 두 판이 같으니
규칙은 이쪽에서 읽고 데이터는 아무 판이나 쓰면 된다.**

## LS 읽개 (한 벌의 객체)

| 자리 | 것 |
|---|---|
| `0x0041C040` | 만들기(`ctor`) |
| `0x0041C070` | **열기** — 머리 `0x110` 바이트를 `this+4` 로 읽고, 첫 청크 자리로 청크 수를 셈해 `this+0x11C` 에 둔다 |
| `0x0041C130` | 닫기 |
| `0x0041C150` | 파일에서 `0x800`바이트씩 채우기(`this+0x120` 담개, `this+0x920` 짚개, `this+0x924` 남은 수) |
| `0x0041C1B0` | **비트 n개 읽기** — MSB 먼저. `this+0x114` 가 지금 바이트, `this+0x118` 이 남은 비트 |
| `0x0041C240` | **심볼 하나** — 1이 이어지는 만큼 세고 그만큼 더 읽는다 |
| `0x0041C290` | **푸는 고리** — 심볼 <256 이면 `this+0x14` 의 글자표를 짚고, 크면 되돌아 베낀다 |
| `0x0041C300` | **청크 읽기(색인, 담을 곳)** — 목록 자리는 `0x110 + 색인*12`. 압축·해제 크기가 같으면 그냥 읽는다 |

객체 속: `+0x00` 파일 손잡이 · `+0x04` 머리 `0x110`바이트(그 안 `+0x14` 가 글자표 256칸) ·
`+0x11C` 청크 수 · `+0x120` 읽기 담개 `0x800` · `+0x920` 짚개 · `+0x924` 남은 바이트.

알맹이는 [2.분석-LS10·LS11 압축 포맷](2.%EB%B6%84%EC%84%9D-LS10%C2%B7LS11%20%EC%95%95%EC%B6%95%20%ED%8F%AC%EB%A7%B7.md) 에 다 옮겨 적었다.

## 세계지도 읽는 곳

`0x00435850` 이 `WORLDMAP.LZW` 를 열어 **청크 하나만** 읽는다 — 청크 번호를 `0x00456E8C`
(한 바이트)에서 가져온다. 곧 게임은 **세로 띠 360칸 폭만 메모리에 얹고 다닌다.**
담개는 `0x00470268` 객체의 `0x0044DFB9` 에서 얻는다.

| 자리 | 것 |
|---|---|
| `0x00435850` | `WORLDMAP.LZW` 열기. 청크 번호를 `0x00456E8C`(한 바이트)에서 가져와 **하나만** 읽는다 |
| `0x0041DD00` | **조각 풀기** — 본보기 표 `0x004582D8`(144바이트 x 6)에서 바탕을 깔고 자국이 켜진 칸만 갈아 끼운다 |

## 아직 안 본 곳

- **팔레트** — DOS `MAIN.EXE` 쪽에서 **모양은 알아냈다.** 붓는 손이 이미지 `0x156B` 다.
```
  lodsw; xchg al,ah; shl al,1; shl al,1; stosb   ; 빨강
  lodsb;             shl al,1; shl al,1; stosb   ; 초록
         xchg al,ah; shl al,1; shl al,1; stosb   ; 파랑
```
  곧 **색 하나가 세 바이트(파랑·빨강·초록), 성분마다 네 비트**이고 두 번 밀어 DAC 여섯
  비트로 만든다. 한 벌이 열여섯 색 48바이트다. 그런 벌이 이미지 `0x3EBCE`·`0x3EBFE`·
  `0x3FB35`·`0x4008E` 등에 여럿 있다 — `0x3EBCE` 를 풀면
  검정·파랑·빨강·자홍·초록·하늘·주황·흰색… 으로 그럴듯하다. **어느 벌이 항해 화면인지가
  남았다.** 바로 앞 `0x3EBB8` 의 `15 13 16 12 02 03 …` 스물두 바이트는 색인 바꿈표로 보인다.
- **통행 판정** — `.data`/`.rdata` 에 256칸짜리 작은 값 표는 없다. 칩 번호(바다 0 · 뭍 `0x41`)를
  보고 가르는 듯한데 자리를 아직 못 찾았다.
- **항해 속도식** — 3편 `0x0048BCF0`(`30.분석-항해 속도(돛·바람·해류)`) 에 해당하는 자리.
- **세이브 `KOUKAI2.DAT`** — `0x00416430` 이 열고 닫는 갈래 넷(`jmp [eax*4 + 0x004164F4]` ·
  `jmp [eax*4 + 0x00416504]` 두 벌의 갈래표)을 가진 손이다. 읽고 쓰는 알맹이는
  `0x004161A0` 과 `0x00415840` 이다.
- **함대 기록** — `0x0046F8C8` 이 함대 기록을 가리키는 포인터고, **맨 앞 두 낱말이 x·y**다
  (바람 짚는 손 `0x0041E270` 이 `[esi]`·`[esi+2]` 를 그대로 쓴다). 좌표는 **칩 눈금**
  (0~2159 / 0~1079)이다. 이 포인터를 짚는 데가 백열여덟 군데라 기록 짜임을 캐기 좋다.
- **바람 흔들기** — `0x00418E80` 이 표값을 가져와 `0x0044E0D2`(무작위) 로 흔든 뒤
  `0x0049F5A0`(바람) · `0x0049F59C` 에 넣는다. **항해 속도식으로 가는 실마리**다.
