# NPK 그림 — GRAPH.DAT · END.DAT · OPEN.DAT

옮긴 자리: `Uw2.Support/Local/Formats/Npk.cs` · 구운 것 `asset/graph/NN.png`(예순아홉 장, 화면 빛깔).

**빛깔** — 머리의 열여섯은 PC-98 기본 빛깔일 뿐이다. 그림 손 `0x0043AC40` 은 머리를 읽고도 빛깔을 걸지 않아 그때 화면 빛깔(바다 화면,
`GamePalette.SeaScreen`)로 찍힌다. 머리 빛깔로 구우면 노랑 · 초록이 튀고, 화면 빛깔로 구우면 살빛이 제대로 나온다.
GRAPH · EVENT · 일기토 그림이 이렇고, OPEN · END 는 실행 파일이 따로 빛깔을 건다(아래).

![GRAPH.DAT 예순아홉 장](graph-sheet.png)

## 몸 — 0x0044D961

그림 찍는 손 `0x0043AC40(x, y, 번호, 갈래)` 가 `GRAPH.DAT` 를 읽어 화면 꼴(`0x0049FB84`)에 따라 푼다. 이 판은 꼴 3 이라
`0x0044D961` 이 돈다(꼴 7 의 `0x0044D692` 는 2 KB 창 LZSS 인데 이 파일들과는 안 맞는다).

네 점이 한 토막이고 줄마다 `(가로 + 3) / 4` 토막이다. 표지 바이트의 비트를 아래부터 하나씩 쓴다.

```
비트 0  날 토막 — 바이트 둘 (a, b). 점 넷이 각 바이트의 비트 7 · 3 에서 나온다.
        색 = a.7 x 8 + a.3 x 4 + b.7 x 2 + b.3   그 뒤 a · b 를 한 칸 왼쪽으로(넷 되풀이)
비트 1  되풀이 — 바이트 하나 c. (c & 0x1F) + 1 토막을 (c & 0x60) / 8 + 4 바이트 앞에서 베낀다.
        c.7 이 서면 거리는 「줄」이다(줄 너비 / 4 x 거리 = 1 ~ 4 줄 위).
```

원본은 다섯 줄 고리 버퍼에 풀어 한 줄씩 화면에 옮긴다. 다 풀면 읽은 바이트가 그림 크기와 꼭 맞는다(예순아홉 장 모두).

실행 파일의 자리 표 `0x004578A0`(자리, 길이 쌍)은 다섯째 장부터 이 `GRAPH.DAT` 와 어긋난다 — 머리 글자로 가른다.

## END.DAT · OPEN.DAT — 빛깔 없는 꼴

머리가 12 바이트뿐이다 — `NPK016`, 가로(+6), 세로(+8), 머리까지 친 길이(+0x0A). 몸은 위와 같은 꼴이라
`0x0042E060` 이 머리를 `0x0049A330` 에 베끼고 `0x00449FD1` 로 넘긴다. END.DAT 쉰다섯 장, OPEN.DAT 아흔 장이 모두 길이대로 꼭 풀린다.

빛깔은 실행 파일에 48 바이트씩 따로 있고 `0x0042E1E0` 이 받는다. 칸마다 **(B, R, G)** 순 0~15 다(사람 살빛으로 맞춰 봤다).

### 주인공 엔딩 — 0x00405B50

`0x0049F5AF`(사람 표 차례)로 갈래를 탄다.

|---|---|---|---|
| 0 조안 | 0x2C7F0 | 0x4545C0 | 누워 책을 읽는다 |
| 1 카탈리나 | 0x5DF1 | 0x4545F0 | 깃펜을 문다 |

### 엔딩 차례 — 0x00404700

엔딩 손(`0x004042C0`)은 「엔딩 이후의 데이터를 저장하겠습니다.」(0x2EA)로 저장을 물은 뒤 `0x004043D7` 에서 `0x00404700(끝 ≠ 0xF)` 을 부른다.
공작 엔딩(0xF)도 같은 손을 탄다. 그림은 모두 `END.DAT` 에서 자리를 바로 짚어 읽는다.

| 것 | 자리 | 크기 | 빛깔 VA |
|---|---|---|---|
| 항해일지 | 0x471EB | 640 x 300 | 0x454590 |
| 램프 두 장 | 0x4F98E · 0x50C5C(한 덩이 0x25E6) | 160 x 104 | 0x454590 |
| 장면 일곱(항구 · 시장 · 주점 · 해전 · 폭풍 · 주인공들 · 책상) | 0x34B20 부터, 크기표 `0x0040548F` | 224 x 160 | 0x456D00 |
| Fin | 0x51F74 | 192 x 80 | 0x456D00 |
| 테두리 | 0x57555 | 640 x 400 | 0x456D00 |

장면 빛깔은 `0x00404EE0` 이 앞 여덟을 지금 빛깔(`0x0049A380`)에서, 뒤 여덟을 장면 표에서 섞는다. 빛깔 넘김(`0x00404E90` · `0x0042E240`)은 옮기지 않았다.

주인공 그림의 움직이는 조각 — `0x00405440` 이 눈(표 `[esp+0xE0]`, 주인공 x 3 + 장) · 촛불(`[esp+0xA4]`, 조안은 없다) 셋씩을
주인공 그림 자리에서 센 거리로 읽는다. 그림 안 자리는 표에 없어(레지스터로 넘긴다) 조각을 그림에 맞대어 찾았다 — 장 하나가 그림과 꼭 같다(`Npk.HeroEndingFrames`).
피에트로의 「눈」 조각은 팔께에, 알의 「촛불」 조각은 둘째 사람 눈께에 있다.

### 여는 화면 — 0x00431930

`OPEN.DAT` 을 열고 장면 손 열둘(`0x00459B38`)을 차례로 부른다. 하나가 글쇠를 받아 참을 돌려주면 나머지를 건너뛴다.
장면마다 (자리, 길이) 쌍과 빛깔을 민다 — 주인공 장면은 모두 `0x004591D0` 이고 이것 하나로 거의 다 맞아 `asset/open/` 은 이 빛깔로 굽는다.

## 시나리오 그림 — EVENT0 ~ 6.DAT

GRAPH.DAT 와 같은 머리 0x30 꼴(제 빛깔)이다. 주인공 시나리오의 `CB x y n`(`0x0043F122` → `0x0043D420`)이 `EVENT(주인공 + 1).DAT` 의
n 번째를 찍는다 — 파일 이름의 숫자는 새 게임 때 `0x00415AD9` 가 주인공(사람 표 차례) + '1' 로 고친다. 자리 표 `0x00456C00`(서른둘)과
바탕 `0x0045E3B0` = [0, 1, 6, 12, 17, 22, 28] 은 파일마다의 장 수 [1, 5, 6, 5, 5, 6, 4] 와 맞는다. `asset/event/F-N.png`.

## 일기토 그림 — IAP1 ~ 6 · IAE1.LZW

LS 묶음, 청크 서른다섯(`Uw2.Support/Local/Formats/DuelSprites.cs`). 다섯씩 일곱 무리 — 몸 하나와 무기 겹그림 넷(무기 갈래 0 ~ 3).
무리는 0 서기 · 맞음 · 쓰러짐 · 이김, 1 찌르기, 2 베기, 3 강타, 4 쳐내기, 5 받기, 6 피하기, 장 수는 [6, 3, 4, 3, 3, 3, 3].
청크 앞 조각 표는 8 바이트씩 (x 8 점 단위, y, 가로 바이트, 세로, 0, 0, 자리 빅엔디언), 몸은 8 점 토막마다 면 바이트 넷이다. 색 8 은 비침.
IAP 는 주인공(왼쪽을 본다), IAE1 은 상대(오른쪽을 본다)이고 둘 다 176 x 120 무대의 제 쪽에 그려져 있어 겹쳐 놓으면 마주 선다.
`asset/duel/NAME-V.png` 는 줄이 무리, 칸이 장인 판이다.
